PROMPT POUR GAMMA AI

Crée une présentation professionnelle de 9 diapositives en français sur le projet Bridge bd_bank.

Public : équipe technique, encadrant de projet et parties prenantes métier.
Style : sobre, clair, moderne, crédible, orienté produit interne bancaire. Éviter le ton publicitaire et les diapositives surchargées. Utiliser peu de texte, des schémas simples et des icônes discrètes. Palette recommandée : vert profond, blanc cassé, gris clair et une touche orange pour les alertes.

Titre du projet : Bridge bd_bank
Sous-titre : Outil interne de vérification de conformité des données bancaires

DIAPOSITIVE 1 — Le problème
Titre : Contrôler les données sans exposer la banque
Contenu :
- Les contrôles métier sont souvent dispersés ou manuels.
- Les anomalies doivent être détectées régulièrement.
- Les données sensibles ne doivent pas être copiées dans les outils de suivi.
Visuel : base de données reliée à une console de contrôle, sans montrer de données réelles.

DIAPOSITIVE 2 — La réponse proposée
Titre : Un pont entre règles métier et données
Contenu :
- L'administrateur écrit une règle lisible.
- Le backend la traduit en SQL paramétré.
- Le moteur exécute le contrôle en lecture seule.
- La console présente les anomalies et leur historique.
Visuel : flux en quatre blocs : règle, moteur, base, alerte.

DIAPOSITIVE 3 — Architecture technique
Titre : Une séparation nette des responsabilités
Contenu :
- Frontend React/Vite pour l'administration.
- API REST Spring Boot pour les échanges JSON.
- ANTLR pour analyser le DSL.
- H2 pour la persistance interne.
- MySQL/PostgreSQL en lecture seule pour bd_bank.
Visuel : diagramme simple frontend -> API -> services -> deux datasources.

DIAPOSITIVE 4 — Le DSL
Titre : Décrire directement l'anomalie
Contenu :
- Règle simple : `comptes.solde < 0`
- Règle entre colonnes : `solde < decouvert_autorise`
- Règle agrégée : `SUM(transactions.montant) < 0 GROUP BY compte_id`
- Fonctions : SUM, COUNT, AVG, MAX, MIN.
Visuel : éditeur de règle à gauche, requête SQL générée à droite.

DIAPOSITIVE 5 — Le cycle de contrôle
Titre : De la règle à l'alerte
Contenu :
1. Lire le périmètre.
2. Parser la règle.
3. Traduire en SQL.
4. Exécuter en lecture seule.
5. Créer ou mettre à jour l'alerte.
6. Résoudre automatiquement si l'anomalie disparaît.
Visuel : frise horizontale en six étapes.

DIAPOSITIVE 6 — La console d'administration
Titre : Une vue de travail, pas un écran décoratif
Contenu :
- Synthèse des alertes actives.
- Liste filtrable des alertes.
- Gestion des règles DSL.
- Schéma et périmètre surveillé.
- Configuration de la fréquence.
Visuel : maquette de dashboard avec une alerte mise en évidence.

DIAPOSITIVE 7 — Confidentialité et sécurité
Titre : Contrôler sans recopier les données bancaires
Contenu :
- Compte SQL dédié limité à SELECT.
- Mots de passe hashés avec BCrypt.
- Sessions avec expiration et logout.
- Blocage après cinq échecs.
- Alertes limitées à l'identifiant et aux colonnes impliquées.
Visuel : bouclier entre la base et la console.

DIAPOSITIVE 8 — Validation du projet
Titre : Un parcours testé de bout en bout
Contenu :
- Parsing et traduction DSL testés.
- Persistance et auto-résolution des alertes testées.
- Scheduler et tests de charge couverts.
- Contrôleurs REST testés, dont login et périmètre.
- Démonstration API réelle validée sur MySQL local.
Visuel : checklist courte avec résultats validés.

DIAPOSITIVE 9 — Démonstration et suite
Titre : Ce que l'on peut montrer aujourd'hui
Contenu :
- Se connecter comme administrateur.
- Choisir les tables surveillées.
- Créer une règle `solde < 0`.
- Observer une alerte active.
- Corriger la donnée de test et montrer la résolution.
- Modifier la fréquence d'analyse.
Suite possible : sessions partagées, notifications, autocomplétion DSL et analyse incrémentale.
Visuel : parcours utilisateur en cinq actions, puis une courte zone "v2".

Consignes de mise en page :
- Une idée principale par diapositive.
- Maximum 4 à 6 éléments visibles par diapositive.
- Privilégier les schémas et les captures de l'interface aux longs paragraphes.
- Ne pas afficher de vrais identifiants, mots de passe ou valeurs bancaires.
- Conserver les exemples DSL courts et lisibles.
